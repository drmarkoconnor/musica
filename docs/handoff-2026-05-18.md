# Handoff - 2026-05-18

## Current Focus

Practice Loop is moving from static lesson scaffolding into the lesson-memory
loop:

```text
live teaching recording -> lesson record -> authorised transcription -> transcript summary -> optional practice notes -> linked audio recall
```

The product direction is intentionally adult-to-adult. Transcript bullets should
capture points of interest from the lesson, not automatically prescribe strict
exercises. Mark chooses which points deserve saving as practice notes.

## Working Locally

- App URL: `http://localhost:3001`
- Tablet/phone microphone testing may need HTTPS because browser mic capture
  usually requires a secure origin. A helper script is available:
  `npm run dev:https`, then try `https://<mac-ip>:3443/lessons`.
- On Netlify, keep API-only secrets scoped to Functions, not Builds:
  `TRANSCRIPTION_PASSWORD`, `OPENAI_API_KEY`, and `DATABASE_URL`. Use a long
  unique transcription password so Netlify's exact-value scanner does not match
  ordinary words in the repo.
- Netlify should supply Blobs context automatically to Functions. If recording
  upload reports `MissingBlobsEnvironmentError`, set a Functions-scoped
  `NETLIFY_BLOBS_TOKEN` Personal Access Token as a fallback.
- Data source: Neon via `.env.local`

## What Works

- Create a draft lesson on `/lessons`.
- Lesson action buttons in the left lesson card now stack vertically, avoiding
  the previous label collision.
- Start a live lesson recording from `/lessons`; this is intended for the
  phone/iPad-on-the-piano use case while Zoom continues on the MacBook.
- Stop the live recording and save it into the selected lesson. If no lesson is
  selected, the recorder creates one. Audio is saved under
  `docs/lesson-recordings/` locally; on Netlify it writes to a Netlify Blobs
  store named `lesson-recordings`, with Neon holding lesson/recording metadata.
- A compact lesson history on `/lessons` lets Mark switch between previous
  lessons and see clip/extract counts, so recordings no longer feel overwritten
  when a newer one appears.
- Attach the central 15-minute test clip to the active lesson.
- Play the lesson audio from the lesson screen.
- Play locally recorded lesson audio from the lesson screen.
- Password modal now transcribes saved local recordings, not only the
  allow-listed test fixture, and refreshes the lesson after completion.
- Passworded transcription now runs a second AI analysis pass that updates the
  lesson summary and inserts clear practice candidates into `lesson_extracts`.
- Raw transcript text is collapsed by default so social chat does not dominate
  the lesson page.
- Teaching segments can be marked and adjusted on a saved recording before
  transcription.
- The transcription modal shows selected segment count/minutes. If no teaching
  segments are selected, full-recording transcription requires explicit
  confirmation.
- Selected teaching segments are clipped server-side with ffmpeg before OpenAI
  transcription, so paid transcription receives only the chosen ranges.
- View a single executive-summary card of lesson points.
- Use a small play control beside each bullet to hear its clip.
- Use the small stop control under the play button to stop the active clip.
- Save a useful point as a lesson-derived practice note.
- See saved lesson-derived notes on `/from-lessons`.
- Password modal authorises transcription and now closes after success instead
  of leaving the modal open.

## Recent Product Decisions

- The 30 second pre-roll and 10 second end-trim idea is only a configurable
  default, not a fixed rule.
- Post-lesson segment review matters because real lessons include social chat,
  setup, and exploratory discussion.
- The first useful review view is an executive-summary card with clip controls,
  not a long transcript block and not a list of automatic exercises.
- Some bullets may include a possible follow-up, but saving one is a manual
  decision.

## Known Gaps

- Uploading arbitrary lesson audio is still placeholder UI.
- Live recording currently keeps browser chunks in memory until stop, then
  uploads the saved blob. This is acceptable for the first local test, but a
  robust one-hour lesson capture should move toward chunked upload or resilient
  background storage.
- Segment clipping uses the packaged `ffmpeg-static` binary, with `FFMPEG_PATH`
  available as an override if the deployment platform needs a different binary.
- Netlify Blobs is the current object-storage bridge for phone testing. Longer
  term, decide whether to keep it or move private audio to Cloudflare R2/S3.
- Lead-sheet PDFs should follow the same object-storage pattern as audio:
  metadata in Neon `piece_assets`, private PDF/image objects in Netlify Blobs
  for prototype or Cloudflare R2/S3 for the durable version.
- The single-card timestamped teaching review is still manually curated for the
  first fixture transcript. Generated lesson summaries currently appear in the
  main lesson summary text and generated practice candidates appear in
  `Extracted candidate practice items`.
- Generated candidates can use original audio times when the selected segment
  labels are present in the transcript. Precision still depends on the AI
  analysis; exact word-level timestamps are not implemented yet.
- Saved practice notes are stored as `practice_tasks`, but the language should
  keep treating them as optional lesson notes/follow-ups, not mandatory exercises.
- Post-lesson segment editing UI does not exist yet.

## Watch For

- Do not send a full one-hour lesson to paid transcription until segment
  selection and cost preview are in place.
- The current live-recorder flow is best tested with a short teaching section
  first, then a longer 10-15 minute section before trusting it for a full hour.
- Keep exact audio timestamps stable when clipping selected segments.
- Avoid making the UI feel like it is judging the lesson or forcing homework.
